# Task 4 - Version-Controlled DevOps Project

## Objective
Manage a DevOps project using Git and GitHub best practices.

## Tools Used
- Git
- GitHub
- Ubuntu Linux
- AWS EC2
- Markdown

## Tasks Performed
1. Created an AWS EC2 environment.
2. Created the DevOps Git project directory.
3. Initialized a Git repository.
4. Created the main branch.
5. Created project documentation using Markdown.
6. Created a .gitignore file.
7. Created a development branch.
8. Created a feature branch.
9. Added and committed project changes.
10. Pushed branches to GitHub.
11. Created Pull Requests.
12. Merged feature changes into the dev branch.
13. Merged dev changes into the main branch.
14. Demonstrated merge conflict resolution.
15. Created a Git tag for the project version.
16. Demonstrated Git stash.
17. Documented Git concepts and interview questions.

## Branching Workflow
feature -> dev -> main

## Expected Outcome
The project demonstrates practical Git version-control practices including commits, branching, Pull Requests, merging, conflict resolution, tags, stash, .gitignore, and Markdown documentation.
